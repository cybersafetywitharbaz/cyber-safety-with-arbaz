## Path Traversal — 5 solved

1. **File path traversal, simple case** — SOLVED 21 Nov 2026. Product image wali request mein filename badla: `GET /image?filename=../../../etc/passwd` — server ne images wale folder se bahar nikal kar `/etc/passwd` file de di; lab page par "LAB ✓ Solved" verify hua. Kyun: har `../` ek folder upar le jata hai — 3 dafa lagane se root tak pohanch kar asal system file parh li gayi, kyunki website ne filename ko check hi nahi kiya tha. Roktham: user ke diye hue filename ko filesystem mein seedha na lagayein; whitelist se check karein aur canonical path ko base folder ke andar hi rakhein.
2. **File path traversal, traversal sequences blocked with absolute path bypass** — SOLVED 21 Nov 2026. Is lab mein `../` wali sequences block thi, lekin `GET /image?filename=/etc/passwd` — seedha full (absolute) path dene se server ne wahi file de di; lab Solved verify hua. Kyun: defense sirf `../` ko rok raha tha, lekin absolute path ko check hi nahi kar raha tha — na-mukammal defense hamesha bypass ho jati hai. Roktham: sirf kuch patterns block karna kaafi nahi; filename ko whitelist aur canonical-path check se guzarna chahiye.
3. **File path traversal, traversal sequences stripped non-recursively** — SOLVED 21 Nov 2026. Website `../` ko ek dafa strip (delete) karti thi, is liye nested sequence lagayi: `GET /image?filename=....//....//....//etc/passwd` — pehli strip ke baad har `....//` asal `../` ban gaya aur file parh li gayi; lab page par "LAB ✓ Solved" (PRACTITIONER) verify hua. Kyun: strip sirf ek layer hatata hai; sequence ko apne andar chhupane se strip ke baad asal traversal dobara ban jati hai. Roktham: strip karne ki bajaye input ko reject karein, aur canonical path check lagayein.
4. **File path traversal, traversal sequences stripped with superfluous URL-decode** — SOLVED 21 Nov 2026. Website filename ko ek se zyada dafa URL-decode karti thi, is liye double-encoded payload lagaya: `GET /image?filename=%252e%252e%252f%252e%252e%252f%252e%252e%252fetc%252fpasswd` — pehli decode par `%2e%2e%2f` bana, doosri par asal `../../../etc/passwd`; file parh li gayi aur lab Solved verify hua. Kyun: decode ki tadad check se zyada thi — jo cheez check ke waqt encoded thi, baad mein decode ho kar traversal ban gayi. Roktham: decode hamesha check se PEHLE, ek hi dafa, mukammal karein; phir canonical path verify karein.
5. **File path traversal, validation of start of path** — SOLVED 21 Nov 2026. Website ye check karti thi ke filename ek makhsoos images-folder path se SHURU ho; payload: `GET /image?filename=/var/www/images/../../../etc/passwd` — filename asal folder `/var/www/images/` se shuru hua (check pass), phir `../` se root tak ja kar `/etc/passwd` parh li; lab page par "LAB ✓ Solved" verify hua. Kyun: check sirf shuruaat (prefix) dekhta tha, ye nahi ke poora path aakhir mein base folder ke andar hi rehta hai ya nahi. Roktham: prefix check kaafi nahi — canonical path ko base folder ke andar verify karna chahiye.
