Kyun: jawab mein chhota sa farq (period ki jagah space) bhi bata deta hai ke ye username asal mein maujood hai, is liye attacker pehle sahi username pakar leta hai aur phir sirf password par zor lagata hai. Roktham: maujood aur ghair-maujood username par har harf tak bilkul ek jaisa jawab dena chahiye.
3. **Broken brute-force protection, IP block** — SOLVED 21 Nov 2026. ## Path Traversal — 5 solved

1. **File path traversal, simple case** — SOLVED 21 Nov 2026. Product image wali request mein filename badla: `GET /image?filename=../../../etc/passwd` — server ne images wale folder se bahar nikal kar `/etc/passwd` file de di; lab page par "LAB ✓ Solved" verify hua. Kyun: har `../` ek folder upar le jata hai — 3 dafa lagane se root tak pohanch kar asal system file parh li gayi, kyunki website ne filename ko check hi nahi kiya tha. Roktham: user ke diye hue filename ko filesystem mein seedha na lagayein; whitelist se check karein aur canonical path ko base folder ke andar hi rakhein.
2. **File path traversal, traversal sequences blocked with absolute path bypass** — SOLVED 21 Nov 2026. Is lab mein `../` wali sequences block thi, lekin `GET /image?filename=/etc/passwd` — seedha full (absolute) path dene se server ne wahi file de di; lab Solved verify hua. Kyun: defense sirf `../` ko rok raha tha, lekin absolute path ko check hi nahi kar raha tha — na-mukammal defense hamesha bypass ho jati hai. Roktham: sirf kuch patterns block karna kaafi nahi; filename ko whitelist aur canonical-path check se guzarna chahiye.
3. **File path traversal, traversal sequences stripped non-recursively** — SOLVED 21 Nov 2026. Website `../` ko ek dafa strip (delete) karti thi, is liye nested sequence lagayi: `GET /image?filename=....//....//....//etc/passwd` — pehli strip ke baad har `....//` asal `../` ban gaya aur file parh li gayi; lab page par "LAB ✓ Solved" (PRACTITIONER) verify hua. Kyun: strip sirf ek layer hatata hai; sequence ko apne andar chhupane se strip ke baad asal traversal dobara ban jati hai. Roktham: strip karne ki bajaye input ko reject karein, aur canonical path check lagayein.
4. **File path traversal, traversal sequences stripped with superfluous URL-decode** — SOLVED 21 Nov 2026. Website filename ko ek se zyada dafa URL-decode karti thi, is liye double-encoded payload lagaya: `GET /image?filename=%252e%252e%252f%252e%252e%252f%252e%252e%252fetc%252fpasswd` — pehli decode par `%2e%2e%2f` bana, doosri par asal `../../../etc/passwd`; file parh li gayi aur lab Solved verify hua. Kyun: decode ki tadad check se zyada thi — jo cheez check ke waqt encoded thi, baad mein decode ho kar traversal ban gayi. Roktham: decode hamesha check se PEHLE, ek hi dafa, mukammal karein; phir canonical path verify karein.
5. **File path traversal, validation of start of path** — SOLVED 21 Nov 2026. Website ye check karti thi ke filename ek makhsoos images-folder path se SHURU ho; payload: `GET /image?filename=/var/www/images/../../../etc/passwd` — filename asal folder `/var/www/images/` se shuru hua (check pass), phir `../` se root tak ja kar `/etc/passwd` parh li; lab page par "LAB ✓ Solved" verify hua. Kyun: check sirf shuruaat (prefix) dekhta tha, ye nahi ke poora path aakhir mein base folder ke andar hi rehta hai ya nahi. Roktham: prefix check kaafi nahi — canonical path ko base folder ke andar verify karna chahiye.

## Business Logic — 4 solved

1. **Excessive trust in client-side controls** — SOLVED 24 Nov 2026. Lab ki shop mein `wiener:peter` se login kiya (store credit $100.00), Lightweight "l33t" Leather Jacket ($1337.00, productId=1) cart mein dala — lekin `POST /cart` request mein chhupa hua `price` parameter (cents mein 133700) client ki taraf se aata hai aur server bina check kiye maan leta hai; wahi POST `price=100` ($1.00) ke saath bheja to cart ka total $1.00 ho gaya, phir cart ke csrf token ke saath checkout POST kiya aur lab ne "Congratulations, you solved the lab!" dikhaya. Kyun: server ne client ki bheji hui price par bharosa kar liya — hidden field ya client-side validation security nahi hai. Roktham: price aur roles hamesha server-side database se check karein; har parameter ko server par validate karein.
2. **High-level logic vulnerability** — SOLVED 24 Nov 2026. Lab ki shop mein `wiener:peter` se login kiya (store credit $100.00), cart mein Lightweight "l33t" Leather Jacket ($1337.00, productId=1) aur Eco Boat ($1.83, productId=16) dala — total $1338.83 ho gaya; phir `POST /cart` mein Eco Boat ki quantity `-700` bhej di (negative quantity), Eco Boat wali line taqreeban -$1279 ho gayi aur cart ka total $57.83 reh gaya, phir cart ke csrf token ke saath checkout POST kiya aur lab ne "Congratulations, you solved the lab!" dikhaya. Kyun: server ne quantity ko check kiye baghair maan liya — negative quantity asal khareed nahi hai, lekin server ne us se total ghata diya. Roktham: quantity hamesha server-side validate karein (quantity > 0 honi chahiye) aur total server-side prices se dobara calculate karein; client ki bheji hui kisi bhi value par bharosa na karein.

3. **Inconsistent security controls** — SOLVED 24 Nov 2026. Exploit server wali email se `arbaz1` user register kiya, Email client se confirm kiya, phir email badal kar `arbaz@dontwannacry.com` kar di — us ke baad Admin panel nazar aane laga aur us se user `carlos` delete kar diya; lab Solved verify hua. Kyun: admin honay ka check user ke email domain par tha, aur email badalne par naye address ki verification hoti hi nahi thi — is liye koi bhi apna email badal kar admin ban sakta tha. Roktham: admin rights sirf server-side explicitly assign karein, email domain par authorization na rakhein, aur naya email verify kiye baghair effective na hone dein.

4. **Flawed enforcement of business rules** — SOLVED 24 Nov 2026. `wiener:peter` se login kiya, newsletter signup (arbaz@example.com) se coupon `SIGNUP30` liya, jacket cart mein dala, phir coupons `NEWCUST5` (-$5.00) aur `SIGNUP30` (-$401.10) ko baari baari 4-4 dafa lagaya — har dafa poori discount dobara kat gayi aur total $0.00 ho gaya — phir order place kiya aur lab Solved verify hua. Kyun: coupon ka rule sirf UI mein tha, server par nahi — server ne ye check hi nahi kiya ke coupon is order par pehle lag chuka hai. Roktham: coupon rules server-side enforce karein (ek order par ek coupon ya clear limit), aur total ko $0.00 se neeche na jaane dein.
